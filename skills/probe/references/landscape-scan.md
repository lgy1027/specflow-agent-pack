# 可选的竞品与参考方案扫描

只有在理解替代方案可能改变决策时才使用。不要因为需求提到 AI 就自动生成通用市场报告。

## 1. 先限定比较范围

搜索前记录目标用户、待完成任务、部署环境、相关市场/地区和需要支持的决定。按当前问题选择“替代方案”范围，可能包括：

- 服务相同用户/任务的直接竞品；
- 可借鉴某个交互或能力的相邻产品/设计参考；
- 商业产品、集成商或合作方；
- 开源项目或研究原型；
- 内部已有组件和历史现场方案；
- 当前人工流程、不建设或延迟决策。

不要仅因产品都带有“AI”标签或属于相同硬件类别就放在一起比较。

## 2. 收集并标明证据等级

优先使用近期一手资料：厂商技术/产品文档、更新日志、价格/条款、兼容性清单、公开演示、标准组织资料或内部实测。二手资料用于发现线索，不要作为关键结论的唯一依据。

每项决策相关主张记录：

- 来源、URL/路径和发布日期/访问日期；
- 证据类型：相关环境实测、规格/文档、厂商声明、第三方报告、类比推断或未知；
- 主张实际覆盖的环境和范围；
- 限制或缺失信息。

产品介绍页只能证明厂商宣称有某能力，不能证明它适配用户工作负载。仓库存在不代表可用于生产。只有在影响采用判断时，才进一步核实许可证、支持平台、维护活跃度和依赖约束。

## 3. 只比较影响当前决策的维度

从用户约束中挑选维度，不用固定加权表。可能的维度包括：

- 用户任务适配和实际工作流；
- 部署环境、形态、安装与运行条件；
- 数据流向、隐私、身份和驻留；
- 集成边界和责任归属；
- 离线/边缘能力、延迟、功耗/热和可靠性；
- 交互质量、易用性和人工接管；
- 有实体动作时的物理动作与安全控制；
- 获取、集成、运营、支持和维护成本；
- 成熟度、锁定、可移植性、许可证和退出成本。

如果负责人给出优先级，清楚列出取舍；不要编造权重或把不同性质的指标加总成一个“赢家”分数。

## 4. 让研究对决策有用

每项保留的发现都回答：**它会改变哪个选项、假设或下一项测试？** 对决策没有影响的发现删掉。如果扫描不会改变建议，就停止，并说明为何跳过或缩小范围。

用带证据链接的方案比较表总结，不堆功能清单。结尾指出最重要的未知项和验证成本最低的方法。将竞品主张与最终建议分开，未验证内容明确标注。
